

- Tauri 2
- React + TypeScript + Vite
- Android 原生 Kotlin
- 主题模式：`system / light / dark`
- 界面模式：Edge-to-Edge
- 同时支持手动切换主题和跟随系统主题。

采用 Tauri 2 原生插件（Kotlin）+ React Theme Provider，而不是直接给 WebView 注入 `JavascriptInterface`。

这样有几个好处：

- 不依赖 Tauri Activity 的内部 WebView 创建回调。
- 通过 Tauri 官方移动插件机制调用 Kotlin。
- React 统一管理主题，Android 只负责系统栏。
- 后续可以继续扩展屏幕方向、状态栏、导航栏、震动等原生功能。

另外，Edge-to-Edge 下状态栏应该保持透明，让 React 页面背景延伸到状态栏后面，而不是试图给状态栏单独设置背景色。Android 15 及以上尤其需要这样处理。

## 二、创建 Android 原生插件

在项目根目录执行：

```
cargo install tauri-cli
cargo install tauri-plugin
```

然后创建插件：

```
cargo tauri plugin new system-bars
```

按照向导选择 Android Kotlin 实现。

这里生成的是独立插件，而不是直接修改 `gen/android` 中的临时文件。

### 1. Kotlin 原生实现

在生成的插件 Android 项目中，找到插件主类，通常是：

```
android/src/main/java/.../SystemBarsPlugin.kt
```

将插件类实现为：

```
package com.plugin.systembars

import android.app.Activity
import android.graphics.Color
import android.os.Build
import app.tauri.annotation.Command
import app.tauri.annotation.InvokeArg
import app.tauri.annotation.TauriPlugin
import app.tauri.plugin.Invoke
import app.tauri.plugin.Plugin
import androidx.core.view.WindowCompat
import androidx.core.view.WindowInsetsControllerCompat

@InvokeArg
class ThemeArgs {
    lateinit var theme: String
}

@TauriPlugin
class SystemBarsPlugin(
    private val activity: Activity
) : Plugin(activity) {

    override fun load(webView: android.webkit.WebView) {
        super.load(webView)

        activity.runOnUiThread {
            // 启用 Edge-to-Edge
            WindowCompat.setDecorFitsSystemWindows(
                activity.window,
                false
            )

            // 系统栏透明，显示 WebView 后面的页面背景
            activity.window.statusBarColor = Color.TRANSPARENT
            activity.window.navigationBarColor = Color.TRANSPARENT

            if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
                activity.window.isNavigationBarContrastEnforced = false
            }
        }
    }

    @Command
    fun setTheme(invoke: Invoke) {
        val args = invoke.parseArgs(ThemeArgs::class.java)

        val isDark = when (args.theme) {
            "dark" -> true
            "light" -> false
            else -> {
                invoke.reject("Invalid theme: ${args.theme}")
                return
            }
        }

        activity.runOnUiThread {
            val controller = WindowInsetsControllerCompat(
                activity.window,
                activity.window.decorView
            )

            // true = 深色图标，false = 白色图标
            controller.isAppearanceLightStatusBars = !isDark
            controller.isAppearanceLightNavigationBars = !isDark

            activity.window.statusBarColor = Color.TRANSPARENT
            activity.window.navigationBarColor = Color.TRANSPARENT

            invoke.resolve()
        }
    }
}
```

注意：

- `system-bars` 是插件名称示例。
- Kotlin package 必须和生成插件的实际包名一致。
- `androidx.core` 依赖需要包含在插件 Android 模块中。
- 不要把这个类放进 `MainActivity.kt`，它是独立的 Tauri 插件。

这里采用 `WindowInsetsControllerCompat`，而不是仅依赖 Android 版本判断，可以兼容更多 Android 版本。

### 2. 注册插件

在 `src-tauri/Cargo.toml` 添加生成插件的本地依赖。假设插件目录是 `plugins/system-bars`：

```
[dependencies]
tauri-plugin-system-bars = { path = "plugins/system-bars" }
```

在 `src-tauri/src/lib.rs` 注册：

```
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_system_bars::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

如果你的项目已经有其他插件，保留原来的 `.plugin(...)`，只增加这一项。

生成插件时，Android Kotlin 类的完整包名和类名应与插件 Rust 初始化代码中的 `register_android_plugin` 保持一致。不要直接把示例中的 `com.plugin.systembars` 当成你生成项目的真实包名。

### 3. 配置权限

打开：

```
src-tauri/capabilities/default.json
```

在 `permissions` 中添加生成插件提供的默认权限：

```
{
  "identifier": "default",
  "description": "Default application permissions",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "system-bars:default"
  ]
}
```

如果插件模板生成的权限标识不同，以它生成的权限文件为准。

## 三、React + TypeScript 主题管理

这里不建议直接在各个组件中修改 `document.documentElement.classList`。

统一使用 ThemeProvider，主题模式只保留三个值：

```
export type ThemeMode = 'system' | 'light' | 'dark';
export type ResolvedTheme = 'light' | 'dark';
```

### 1. 创建主题服务

`src/services/theme.ts`

```
import { invoke, isTauri } from '@tauri-apps/api/core';

export type ThemeMode = 'system' | 'light' | 'dark';
export type ResolvedTheme = 'light' | 'dark';

const STORAGE_KEY = 'app-theme';

export function getThemeMode(): ThemeMode {
  const value = localStorage.getItem(STORAGE_KEY);

  if (
    value === 'system' ||
    value === 'light' ||
    value === 'dark'
  ) {
    return value;
  }

  return 'system';
}

export function saveThemeMode(mode: ThemeMode) {
  localStorage.setItem(STORAGE_KEY, mode);
}

export function resolveTheme(mode: ThemeMode): ResolvedTheme {
  if (mode === 'system') {
    return window.matchMedia(
      '(prefers-color-scheme: dark)'
    ).matches
      ? 'dark'
      : 'light';
  }

  return mode;
}

export async function updateNativeTheme(
  theme: ResolvedTheme
) {
  if (!isTauri()) return;

  if (!/Android/i.test(navigator.userAgent)) return;

  try {
    await invoke('plugin:system-bars|setTheme', {
      theme,
    });
  } catch (error) {
    console.error('Update Android system bars failed:', error);
  }
}
```

这里的 `invoke` 使用 Tauri 2 官方 API。插件命令的调用形式为 `plugin:插件名称|命令名称`。

### 2. 创建 ThemeProvider

`src/providers/theme-provider.tsx`

```
import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useState,
  type ReactNode,
} from 'react';

import {
  getThemeMode,
  saveThemeMode,
  resolveTheme,
  updateNativeTheme,
  type ThemeMode,
  type ResolvedTheme,
} from '@/services/theme';

interface ThemeContextValue {
  mode: ThemeMode;
  theme: ResolvedTheme;
  setMode: (mode: ThemeMode) => void;
}

const ThemeContext = createContext<ThemeContextValue | null>(
  null
);

export function ThemeProvider({
  children,
}: {
  children: ReactNode;
}) {
  const [mode, setMode] = useState<ThemeMode>(getThemeMode);

  const [systemDark, setSystemDark] = useState(
    () =>
      window.matchMedia(
        '(prefers-color-scheme: dark)'
      ).matches
  );

  const theme: ResolvedTheme =
    mode === 'system'
      ? systemDark
        ? 'dark'
        : 'light'
      : mode;

  const changeMode = useCallback((nextMode: ThemeMode) => {
    saveThemeMode(nextMode);
    setMode(nextMode);
  }, []);

  // 监听 Android / 系统主题变化
  useEffect(() => {
    const media = window.matchMedia(
      '(prefers-color-scheme: dark)'
    );

    const handleChange = (event: MediaQueryListEvent) => {
      setSystemDark(event.matches);
    };

    media.addEventListener('change', handleChange);

    return () => {
      media.removeEventListener('change', handleChange);
    };
  }, []);

  // 同步 Web 页面主题
  useEffect(() => {
    document.documentElement.classList.toggle(
      'dark',
      theme === 'dark'
    );

    document.documentElement.style.colorScheme = theme;
  }, [theme]);

  // 同步 Android 状态栏和导航栏
  useEffect(() => {
    void updateNativeTheme(theme);
  }, [theme]);

  const value = useMemo(
    () => ({
      mode,
      theme,
      setMode: changeMode,
    }),
    [mode, theme, changeMode]
  );

  return (
    <ThemeContext.Provider value={value}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);

  if (!context) {
    throw new Error(
      'useTheme must be used inside ThemeProvider'
    );
  }

  return context;
}
```

### 4. 页面中切换主题

例如使用 shadcn/ui 的 Select：

```
import { useTheme } from '@/providers/theme-provider';

export function ThemeSwitcher() {
  const { mode, setMode } = useTheme();

  return (
    <select
      value={mode}
      onChange={(e) =>
        setMode(e.target.value as typeof mode)
      }
    >
      <option value="system">跟随系统</option>
      <option value="light">浅色模式</option>
      <option value="dark">深色模式</option>
    </select>
  );
}
```

效果：

| 主题设置   | 页面   | Android 状态栏图标 |
| ------ | ---- | ------------- |
| system | 跟随系统 | 自动同步          |
| light  | 强制浅色 | 深色图标          |
| dark   | 强制深色 | 白色图标          |

## 四、Edge-to-Edge CSS 适配

这一步非常重要，否则状态栏虽然透明了，但页面顶部内容可能会被时间、电量图标遮挡。

### 1. index.html

确保 viewport 配置包含 `viewport-fit=cover`：

```
<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, viewport-fit=cover"
/>
```

### 2. 全局 CSS

`src/index.css`

如果使用 Tailwind CSS 4：

```
@import "tailwindcss";

:root {
  color-scheme: light;
  --app-background: #ffffff;
}

.dark {
  color-scheme: dark;
  --app-background: #121212;
}

html,
body,
#root {
  width: 100%;
  min-height: 100%;
  margin: 0;
}

body {
  background: var(--app-background);
}

#root {
  min-height: 100dvh;
  background: var(--app-background);
}

/* 页面顶部安全区域 */
.safe-top {
  padding-top: env(safe-area-inset-top, 0px);
}

/* 页面底部安全区域 */
.safe-bottom {
  padding-bottom: env(safe-area-inset-bottom, 0px);
}

/* 页面内容区域 */
.app-content {
  min-height: 100dvh;
  box-sizing: border-box;
  background: var(--app-background);
}
```

使用示例：

```
function Layout() {
  return (
    <div className="app-content">
      <header className="safe-top">
        <h1>Fitodo</h1>
      </header>

      <main>
        页面内容
      </main>

      <footer className="safe-bottom">
        底部导航
      </footer>
    </div>
  );
}
```

注意：如果 Android WebView 没有提供对应的 `safe-area-inset-*` 值，需要再通过原生 `WindowInsets` 获取实际尺寸，并传递给 Web 页面。不要同时对同一安全区域重复添加 padding。


## 七、一个重要的工程建议

项目建议将原生系统 UI 能力独立封装，不要让 React 直接依赖 Android 实现细节。

建议最终目录：

```
src/
├── providers/
│   └── theme-provider.tsx
├── services/
│   └── theme.ts
├── hooks/
│   └── use-theme.ts
├── components/
│   └── theme-switcher.tsx
└── index.css

src-tauri/
├── src/
│   └── lib.rs
├── capabilities/
│   └── default.json
└── plugins/
    └── system-bars/
        ├── src/
        ├── permissions/
        └── android/
            └── src/main/java/
```
